        <div>
            <h2 class="section-title">What is Karuta?</h2>
            <p>Karuta is a declarative logic programming language that marries the elegance of Prolog with the robustness of the Erlang BEAM virtual machine. It is named after the Japanese card game that rewards quick pattern recognition.</p>
            <p>Unlike imperative languages where you specify <em>how</em> to compute something, Karuta lets you declare <em>what</em> you want to compute. The runtime handles the execution strategy, so you can focus on the problem domain.</p>
            <p>Built on the BEAM, Karuta inherits decades of production-proven fault tolerance and scalability. Use it for intelligent systems, knowledge bases and rule engines.</p>
        </div>
    </section>

    <section class="band" id="relational-types">
        <h2 class="section-title">Relations as <span class="acc">predicates</span></h2>
        <p class="sec-intro">In Karuta, relations are not tables. They are predicates in a logical system, each representing facts that can be true or false.</p>
        <div class="grid two">
            <div class="grid-item">
                <h3>Formal logical foundation</h3>
                <p>Karuta builds on relation theory and simple set theory expressible in first-order predicate logic (SST/FOPL). Database operations are logical inferences, not only data transformations. Each relation states facts about your domain, and querying is reasoning about what must be true given those facts.</p>
            </div>
            <div class="grid-item">
                <h3>Semantic consistency</h3>
                <p>Relations carry meaning from your conceptual model, so Karuta can keep your data logically consistent. Constraints are formal expressions of your business logic in predicate logic, and contradictions are caught at compile time rather than at runtime.</p>
            </div>
        </div>
    </section>

    <section class="band" id="prolog-power">
        <h2 class="section-title">The power of Prolog</h2>
        <div class="grid">
            <div class="grid-item">
                <h3>Declarative clarity</h3>
                <p>Express what you want to achieve rather than how. Write specifications, not implementations; the inference engine picks the execution strategy.</p>
            </div>
            <div class="grid-item">
                <h3>Unification</h3>
                <p>Unification solves equations, instantiates variables and discovers relationships in both directions. One predicate can work in several modes.</p>
            </div>
            <div class="grid-item">
                <h3>Backtracking and search</h3>
                <p>Write rules for what a valid solution is, and the runtime explores the possibilities. Good for constraint solving, planning and puzzles.</p>
            </div>
            <div class="grid-item">
                <h3>Natural recursion</h3>
                <p>Recursion is how logic programs iterate. Tail-recursive predicates are optimized automatically.</p>
            </div>
            <div class="grid-item">
                <h3>Symbolic computation</h3>
                <p>Manipulate symbols and structures directly. Suited to compilers, interpreters, theorem provers and other systems that reason about symbols.</p>
            </div>
            <div class="grid-item">
                <h3>Knowledge representation</h3>
                <p>Express domain knowledge as facts and rules that mirror human reasoning. Build expert systems, decision support tools and agents.</p>
            </div>
        </div>
    </section>

    <section class="band" id="domino">
        <h2 class="section-title">Domino</h2>
        <p class="sec-intro">At the heart of Karuta lies Domino, an implementation of the Semantic-Relational Data Model using Mnesia, bringing formal logic to database design on the BEAM.</p>
        <div class="grid">
            <div class="grid-item">
                <h3>From conceptual to logical models</h3>
                <p>Database design starts with conceptual models: object types and their defining properties, in natural language. Domino formalizes them as logical models using relation theory and first-order predicate logic. The symbols acquire meaning while keeping their mathematical properties, so they support both algebraic manipulation and semantic reasoning.</p>
            </div>
            <div class="grid-item">
                <h3>Properties as first-class types</h3>
                <p>Objects are recognized by their observable, defining properties. When properties persistently co-occur, we infer an object type and name it. Relationships between objects are collective properties of the compound object they form, which removes the usual confusion between properties and relationships.</p>
            </div>
            <div class="grid-item">
                <h3>Semantic constraints as logic</h3>
                <p>Relations in Domino are predicates, and semantic constraints keep your data faithful to your conceptual model. Combined with Karuta, Domino turns Mnesia into an active knowledge base that validates itself and answers queries in pure logic, with ACID guarantees across the BEAM cluster.</p>
            </div>
        </div>
    </section>

    <section class="band" id="beam">
        <h2 class="section-title">Built on <span class="acc">the BEAM</span></h2>
        <p class="sec-intro">The BEAM has powered critical telecommunications infrastructure for over three decades. Karuta brings logic programming to this proven platform.</p>
        <div class="grid">
            <div class="grid-item">
                <span class="eyebrow">Let it crash</span>
                <h3>Fault tolerance</h3>
                <p>Supervisor trees restart what fails. Process isolation keeps failures contained and recovery automatic.</p>
            </div>
            <div class="grid-item">
                <span class="eyebrow">Millions of processes</span>
                <h3>Scalability</h3>
                <p>Each logical computation can run in its own lightweight process. Scale on one machine, then across a cluster.</p>
            </div>
            <div class="grid-item">
                <span class="eyebrow">Zero downtime</span>
                <h3>Hot code swapping</h3>
                <p>Deploy new versions of your rules while the system keeps running.</p>
            </div>
            <div class="grid-item">
                <span class="eyebrow">One logical system</span>
                <h3>Distribution first</h3>
                <p>Knowledge bases span nodes transparently. Mnesia replicates data and processes talk across the network as easily as locally.</p>
            </div>
            <div class="grid-item">
                <span class="eyebrow">Per-process GC</span>
                <h3>Soft real-time</h3>
                <p>A preemptive scheduler and per-process garbage collection keep response times steady under load.</p>
            </div>
            <div class="grid-item">
                <span class="eyebrow">Look inside</span>
                <h3>Observability</h3>
                <p>Inspect running systems with the observer, trace message flows and debug live production nodes.</p>
            </div>
        </div>
